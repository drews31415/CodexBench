# 웹 대시보드 고도화 기록 (2026-11-28)

GitHub Pages 대시보드(https://drews31415.github.io/CodexBench/dashboard/)를 처음 보는 심사위원과 개발자가 AAH의 문제의식, Codex 활용 방식, 핵심 기술, 결과와 한계를 짧은 시간에 이해하고 실제 증거로 이동할 수 있도록 고친 기록이다. 모델·Codex 호출 0회. 연구 정책, 동결 분석 코드, 기존 실험 결과, 제출 고정본은 바꾸지 않았다.

## 1. 범위와 원칙

- 수치는 모두 `public_data/`(동결 분석 산출물과 실행 기록에서 내보낸 공개 데이터)에서 화면이 직접 계산한다. 화면 문구에 고정 숫자를 적지 않았다.
- 라이브(유효), 무효(v1), 합성(S3, 모델 호출 0)을 화면마다 구분하고 합산하지 않는다. 원인 후보는 "가설"로만 표시한다.
- 제출 고정본 `docs/submission/dashboard.html`은 바이트 단위로 유지한다. 이전 화면 원본을 `analysis/dashboard/submission-2026-11-27/`에 고정하고 `submission_bundle`이 그것만 쓰게 했다(`SUBMISSION_BUNDLE_REPRODUCED` 유지).
- 정적 단일 HTML, CSP `default-src 'none'`, 외부 의존성 0을 유지했다. 새 프레임워크나 패키지는 쓰지 않았다(브라우저 검사도 Node 내장 기능과 로컬 Chrome만 사용).

## 4. 새 데이터: 과제별 Repository Graph

- `python -m analysis.repository_graphs build|check` — `benchmarks/main_public/<task>/base`의 공개 파일만 읽어, 바꾸지 않은 `aah.graphs.repository.build`로 추출한다. 출력 `public_data/repository_graphs/<task>.json`, `MANIFEST.json`(파일 해시, 원본 revision).
- 화면에 "현재 저장소에서 재추출 · 실험 시점 기록 아님"을 표시한다. 같은 과제에 라이브 그래프 진단 기록이 있으면 코드 쪽 노드·관계를 대조해 "일치/다름"을 보인다(제출본 기준 C03·D02·D04·R03·R04·S02·S03의 v1 기록 8건, D04의 v2 기록 1건). 2026-11-28 확인 결과 9건 모두 코드 노드·관계가 재추출 그래프와 일치했다. C02는 그래프 진단 기록이 없어 대조할 기록이 없다고 표시한다.
- task.json에서는 `task_id`, `repo_id`, `task_family_id`, `allowed_change_paths`, `approved_check_ids`만 읽는다. 비공개 검사·정답 패치는 이 경로에 없다.

배지는 테두리 없는 점+글자로, 헤더의 데이터 해시 칩은 감사 화면으로 옮겼다. 데스크톱 페이지 높이(같은 1366px 창): 개요 4,450 → 1,581px, 조건 비교 3,395 → 2,385, 실행 추적 3,006 → 1,071, 컨텍스트 3,055 → 1,364, 그래프 1,636 → 1,027, Replay 1,166 → 900. 실험 감사는 개요에서 옮겨 온 내용 때문에 3,776 → 4,361로 늘었다. 모바일 개요 9,318 → 1,465px.

# S3 이중 그래프 및 복구 전략 검증

2026-11-26 · IP15–IP19 · 조건 D · 오프라인 전체 테스트 172개 통과 (S3 테스트 15개 포함)

조건 D는 공통 감지기와 개입 게이트가 복구를 허용한 시점에 저장소 그래프와 실행 그래프를 연결한다. 공개 실패에서 도달한 코드 후보와 경로, 선택한 전략, 실제로 전달한 메시지 해시, 후속 턴의 관측을 같은 실행 ID로 조회할 수 있다.

## 구현과 검증 범위

| 작업 | 확인한 동작 |
| --- | --- |
| IP15 저장소 그래프 | 검증된 공개 스냅샷 바이트에서 Python 파일, 클래스, 함수, 테스트와 정적으로 해석 가능한 관계를 추출한다. 파싱 실패는 파일 노드와 경고로 남긴다. 이름이 가려진 호출, 동적 호출 및 해석되지 않은 import는 미해결로 기록한다. 파일 이동 전후 심볼은 별도 ID를 사용한다. |
| IP16 실행 그래프 | 정규화된 원장과 승인 검사에서 사건과 결과를 연결한다. 출처 순서가 있을 때만 NEXT를 만든다. 같은 실패는 검사 정의·환경·테스트가 비교 가능한 직전 검사에만 연결한다. 중간 PASS가 있으면 사슬을 끊는다. |
| IP17 교차 연결 | 버전과 공개 테스트 ID, traceback 줄, 관측된 파일 읽기, 변경 전후의 diff 범위를 확인한다. 위치를 확정할 수 없는 연결은 미해결 기록으로 보존한다. |
| IP18 제한 탐색 | 깊이 4, 상태 200개, 분기 20개, 후보 8개를 적용한다. 탐색 방향, 엣지별 비용, 점수와 중단 사유를 기록한다. 같은 비용과 깊이에서는 시간적 선후에 덜 의존하는 경로를 우선한다. 수정과 실패의 관련성을 주장하려면 별도의 위치 또는 테스트 연결 근거가 필요하다. |
| IP19 전략 및 D 통합 | D는 초기·복구 모두 DEFAULT를 사용한다. 반복 실패, 회귀 및 일반 재시도를 합성 후속 턴에서 확인했다. 과거 코드 위치만 남은 별도 통합 테스트에서는 `REFRESH_EVIDENCE`와 과거 버전 표시를 전달했고, 후속 턴의 현재 파일 읽기를 관측했다. 이 사례에서 공개 검사는 계속 FAIL이었다. |

현재 파일 접근 로그는 모든 읽기를 포괄하지 않으므로 미탐색 가점은 0이고 접근 범위는 `unknown`이다. 복구 지침을 전달했어도 해당 행동을 확인할 증거가 없으면 수행 판정은 `unknown`이다. 동적 호출이나 traceback 일부가 빠진 그래프는 `partial`일 수 있으며, 그 안의 검증된 경로는 사용할 수 있다.

테스트는 그래프 계산 오류 시 조건 D를 유지한 평면 복구, 무결성 오류 시 후속 턴 중단, 유형별 핵심 근거가 예산을 넘을 때 한 번의 일반 재구성, 일반 근거도 초과할 때 예약 전 중단을 포함한다. B와 D의 최초 메시지 바이트 일치, A/B/C의 그래프 미호출 및 D의 DCC 미호출도 확인했다.

탐색 정체(T2) 단위 테스트에서 반복 검색의 결과가 실제 파일 읽기 이벤트를 가리킬 때 해당 파일의 내부 의존성을 복구 대상으로 찾았다. 같은 입력에서 결과 참조를 제거하면 일반 재시도를 선택했다.

## 재현

저장소 루트의 Python 환경에서 실행한다. 프로젝트의 그래프 의존성은 NetworkX 3.2 이상 4 미만이다.

```powershell
$env:PYTHONPATH = (Resolve-Path src).Path
python -m benchmarks.smoke.s1 --condition D --output-dir results/s3-verification
python -m benchmarks.smoke.s3 --scenario repeat --output-dir results/s3-verification
python -m benchmarks.smoke.s3 --scenario regression --output-dir results/s3-verification
python -m pytest -q -m 'not live'
```

실행별 `results/s3-verification/<실행 ID>/interventions.jsonl`의 첫 행에 그래프와 진단 추적 ID가 있다. 같은 실행의 `graphs/`에서 해당 ID의 JSON을 열면 경로와 근거를 확인할 수 있다. `context.jsonl`은 전달 메시지의 해시와 필수 근거를, `evidence.jsonl`과 `checks.jsonl`은 후속 행동과 공개 판정을 담는다.

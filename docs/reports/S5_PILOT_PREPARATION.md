## Pilot 실행 승인

사용자가 이 대화에서 제안된 Pilot 범위를 승인했다. DEV-01~05 × A–E 각 1회, 최초 25턴과 복구 최대 40턴, 추가 결제 한도 0원이다. [승인 기록](../../configs/pilot/dev-pilot-20261126-approval.json)

실행기는 승인된 초안과 과제 파일의 해시를 대조한다. 각 슬롯에 한 번만 최초 턴을 예약하고 B–E의 복구를 같은 세션에서 최대 두 번 전달한다. 이전 실행 기록이 있으면 판정에 연결해 재사용한다.

Pilot의 공개 검사는 작업 스냅샷에 묶이고, 독립 평가는 별도 프로세스에서 동결 패치를 재생한다. 두 경로는 모델 후보의 계산을 고정 Docker 이미지에서 실행한다. 작업 코드에는 각 검사의 입력만 제공한다. 후보가 순수 Python으로 제한된 평가 문법 범위를 벗어나면 `SUBMISSION_BOUNDARY_UNVERIFIED`와 `NOT_RUN`을 기록한다.

모의 전송으로 25슬롯의 보고서·독립 판정 연결과 재실행 시 중복 호출 0건을 확인했다. 런타임 테스트는 복구 2턴까지 허용하고 3번째 복구를 전달 전에 거부했다. 과제 5개의 기준본·참조본은 로컬 테스트용 전송에서 공개·별도 평가 사례의 계산 결과를 확인했다. Pilot 실행기 테스트 9건은 모두 통과했다. 전체 회귀 테스트 중 Pilot manifest 변경으로 실패한 재생 테스트와 Windows 평가 프로세스가 종료된 S4 테스트는 각각 단독 재실행에서 통과했다. [Pilot 실행기 통합 테스트](../../tests/integration/test_pilot_execution.py)

### 복구와 조건 동등성

- 첫 턴 공개 검사 실패 12건 중 A에서 발생한 4건은 설계상 외부 개입을 사용하지 않았다. B–E에서 발생한 8건에는 같은 세션으로 복구 메시지를 각각 한 번 전달했고, 모두 후속 턴 완료 이벤트를 관측했다. 최종 독립 평가에서 그중 5건이 PASS였다.
- 복구를 전달한 8건은 모두 반복 실패 `T1`과 `GENERIC_RETRY`를 기록했다. D·E의 5건에서는 그래프가 유형별 전략을 선택할 근거를 확보하지 못해 일반 재시도로 전환했다. 그래프 기반 유형별 복구의 효과는 이 Pilot에서 측정할 수 없었다.
- 복구 후 실패한 3건은 동일 체크포인트에서 추가 개입을 차단하는 `DUPLICATE_CHECKPOINT`와 `NO_SAFE_CONTINUATION`을 기록했다. 세 건의 마지막 패치는 독립 평가를 받았다.
- 모든 과제에서 B/D와 C/E의 최초 메시지 해시가 각각 일치했다. 25슬롯의 공개 보고서, 동결 패치, 독립 평가 요청·결과 해시를 대조했다. 실행별로 서로 다른 최초 세션을 사용했고, 복구는 해당 실행의 세션을 재개했다.

### 자원 관측과 다음 게이트

최초 25턴과 복구 8턴으로 승인 상한 65턴 중 33턴을 사용했다. 25슬롯 모두 CLI 이벤트의 모델 토큰을 관측했고, 평균은 91,925.76토큰, 중앙값은 78,632토큰이었다. 실행과 독립 평가의 시간 합계는 976.602초(약 16분 17초)였고, 슬롯당 중앙값은 37.389초였다. 이 합계에는 전체 사전 점검과 슬롯 사이 대기 시간이 포함되지 않는다. 화폐 결제액, 크레딧 환산과 계정 잔여량은 로그에서 확인되지 않았다.

Pilot의 실제 A–E 비교·복구 전달·독립 판정·사용량 확인을 마쳤다. 공통 체크포인트의 해시 일치 및 B–E 새 세션 복원에는 S4 합성 검증 기록이 있다. 이번 승인 범위는 end-to-end 비교 25슬롯으로, 실제 공통 체크포인트 분기 증거는 미확보다. 관측한 첫 턴 공개 실패율 12/25는 실제 분기 가능 체크포인트 확보율과 단위가 다르다.
